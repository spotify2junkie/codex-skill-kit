# explain-eli5

将用户提供或指向的学习资料做成能一遍看懂的图解 HTML 页面，发布成 Artifact。调用形式：`$explain-eli5 学习资料或链接`；也识别用户写的 `/explain-eli5` 或 `explain-eli5`。若没有资料且上下文也没有可用资料，先索取资料，不凭空选题。

读取并结合相邻 `../eli5/SKILL.md` 的受众解释方法；本技能的具体要求优先。默认读者对主题没有基础，所有术语第一次出现时用一句话解释，先说结论再说原理。简化表达不能牺牲事实准确性。

## 内容结构

1. 先读完全部材料，提炼 8–13 个核心概念，按“后一个概念是为了解决前一个概念带来的问题”的依赖顺序排列；顺序本身传达信息，不照搬材料顺序。不得为凑数量虚构概念或依赖关系。
2. 找出贯穿全部概念的一条主线：主循环、流水线或核心矛盾。页面顶部用一句话和一张图呈现。
3. 每个概念一张卡片，卡片是一幅两格漫画：左格“烦恼”（没有这个概念会发生什么），右格“办法”（这个概念如何解决）。漫画下面只写两行：“解决了什么”“代价是什么”，不得添加第三行。首次术语解释可放在卡片标题旁或节内简短引导中，不能破坏这两行限制。
4. 所有图用同一组固定角色贯穿，例如 A、B、C 三个老请求与 D 一个新请求；按领域选择合适角色。计算采用便于读者手算的小数字，并明确标注“示意值”。示意值是教学假设，不得冒充材料数据；实际数字以材料为准，材料没有的事实性数字必须联网核实，不凭印象填写。
5. 页面末尾放一把“尺子”：该领域衡量好坏的 2–3 个指标，在同一张图上说明每种办法通常改善哪个、牺牲哪个。不要虚构必然的取舍。
6. 若用户指出材料中卡住的地方，单独添加“零基础版”，逐步说明每一步发生了什么，并配一张对比表。
7. 最后提供“一遍过完”的学习路线：3–4 站，每站写为什么去、去多久、链接。每个链接必须联网打开核实真实存在且内容相关，不能编造；时长标为建议学习时长。

## 视觉风格：卡通手绘

- 同时设计浅色和深色主题：浅色用方格纸或笔记本底色，深色用黑板粉笔感；提供主题切换。
- 中文标题用 Google Fonts 的 Ma Shan Zheng，英文和数字用 Patrick Hand，正文用系统无衬线字体保证可读，并提供字体加载失败时的回退字体。
- 卡片使用不规则圆角手绘边框、轻微旋转、硬阴影。
- 所有图使用手写的内联 SVG，不用图表库。图形应用轻微的 `feTurbulence` + `feDisplacementMap` 抖动滤镜，文字置于滤镜组外，不抖动。
- 固定颜色语义：绿色＝正在进行，橙色＝新来的，蓝色＝存起来的，红色虚线＝被释放或作废。配文字或形状辅助区分。
- 卡片右上角放手绘进度印章：“已学 / 补一下 / 下一站”。允许用户切换状态；未提供进度时不假定已学。
- 每格漫画的说明文字总计不超过 15 个汉字。文字不能压边框或互相重叠；为文字预留空间。
- 以图为主，每节正文不超过四句话。“零基础版”需要较长步骤时拆成短小子节。

## 制作、验证与发布

在当前环境中使用可用的网页构建和发布能力。若使用 Sites，读取可用的 `sites:sites-building` 和 `sites:sites-hosting` 技能并按其流程执行，将 HTML 页面发布成可访问的 Artifact。

发布前必须用 headless Chrome 渲染整页截图，实际查看所有图，检查两套主题以及窄屏下的文字重叠、越界、裁切、滤镜、颜色和进度印章。发现问题先修复，再截图复核，之后才能发布。若无法运行要求的渲染验证或发布能力不可用，说明具体阻塞并保留本地 HTML，不声称已验证或已发布。

发布成功后给出真实访问链接，并用 5–8 个要点介绍页面结构。
