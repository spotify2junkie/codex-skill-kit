# Investigation

The parent owns the answer. Follow `../references/codex-agent-runtime.md` when
using task history, delegation or connectors.

For read-only questions and reviews, inspect the relevant source and produce a
cited explanation or prioritized recommendation. State the evidence boundary:
which revision, tasks or real surface were checked and what remains unverified.

Use a bounded executable experiment when it can distinguish competing claims.
A failed environment setup is not evidence of a product defect. Reconcile task
history with current Git, PR and runtime state; historical instructions do not
grant new authority.

Optional supporting skills may help a specific question when visible. Missing
`how`, `why` or writing aliases do not block investigation and do not require
installing a skill. Follow the parent SKILL.md's progressive-loading rule.

Read-only scope does not create a PR or trigger release. When the user requests
implementation, continue with the relevant implementation playbook and existing
evidence. Report findings, their implications and the concrete next change.
