# Feature

Follow [Poteto Mode](../SKILL.md) for activation, authority, and delivery boundaries.

Define the user-visible behavior and any changed public contract or state transition. Inspect the affected subsystem and its existing conventions; consult architecture guidance only when a consequential design choice remains unresolved.

Implement the feature in the permitted checkout. Split work only when the pieces can be owned independently; direct implementation is appropriate for coupled or small changes. Do not require extra skills, competing implementations, or reviewer agents merely because code is being added.

Verify the meaningful interaction or contract and run required checks. Cover loading, failure, concurrency, or persistence where the feature actually introduces those behaviors. Fix failures caused by the change and complete the authorized delivery step. Create a PR only when included in that scope.

Report the behavior delivered, significant choices, verification, and remaining limitations.
